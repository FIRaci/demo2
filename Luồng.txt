PHẦN 1: TỔNG QUAN VỀ CƠ CHẾ HOẠT ĐỘNG CỦA SPRING BOOT (CONTAINER, BEAN & ANNOTATION)
================================================================================

1. Spring IoC Container (ApplicationContext) là gì?
   - Trong ứng dụng Java truyền thống, bạn phải tự gõ `new EmployeeServiceImpl()` để tạo đối tượng.
   - Trong Spring Boot, bạn KHÔNG KHỞI TẠO ĐỐI TƯỢNG BẰNG TỪ KHÓA `new` thủ công.
   - Ngược lại, **Spring IoC Container (Inversion of Control - Đảo ngược điều khiển)** là một "Nhà máy/Quản gia" toàn năng.
   - Khi chạy lệnh `SpringApplication.run(HrmApplication.class, args)`:
     + Spring sẽ thực hiện **Component Scan**: Quét toàn bộ gói `com.example.hrm` và các thư mục con.
     + Tìm tất cả các Class được đánh dấu Annotation (`@Component`, `@Service`, `@Repository`, `@RestController`, `@Configuration`).
     + Tự động khởi tạo các Class đó thành các đối tượng duy nhất (gọi là **Beans**) và quản lý tập trung trong bộ nhớ (ApplicationContext).

2. Dependency Injection (Tiêm phụ thuộc qua Constructor):
   - Khi `EmployeeController` cần sử dụng `EmployeeService`, thay vì khởi tạo `new EmployeeServiceImpl()`, ta khai báo:
     ```java
     private final EmployeeService employeeService;
     public EmployeeController(EmployeeService employeeService) {
         this.employeeService = employeeService;
     }
     ```
   - Spring IoC Container sẽ tự động tìm thấy Bean `EmployeeServiceImpl` đã khởi tạo sẵn và "tiêm" (Inject) nó vào `EmployeeController`.
   - Lợi ích: **Low Coupling (Độ phụ thuộc thấp)** & **High Cohesion (Tính đóng gói cao)** chuẩn SOLID.

3. Giải thích Ý nghĩa & Cơ chế của từng Annotation trong dự án:

   A. `@SpringBootApplication` (tại `HrmApplication.java`):
      - Là tổ hợp của 3 Annotation: `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan`.
      - Báo cho Spring Boot tự động bật máy chủ web ngầm Tomcat (Cổng 8080) và quét toàn bộ dự án.

   B. `@RestController` (tại `AuthController.java`, `EmployeeController.java`):
      - Là tổ hợp của `@Controller` + `@ResponseBody`.
      - Biến Class thành một Cổng tiếp nhận Web API RESTful.
      - Mọi dữ liệu trả về từ hàm (như `ResponseEntity<ApiResponse>`) sẽ được Spring tự động chuyển thành chuỗi chuẩn **JSON** cho Trình duyệt đọc.

   C. `@Service` (tại `AuthServiceImpl.java`, `EmployeeServiceImpl.java`):
      - Khai báo Class chứa Logic Nghiệp vụ. Spring sẽ đăng ký nó thành một Service Bean trong Container.

   D. `@Repository` (tại `EmployeeRepository.java`, `UserAccountRepository.java`):
      - Khai báo Class/Interface thao tác với Database.
      - Khi kế thừa `JpaRepository`, Spring Data JPA dùng **Dynamic Proxy** để TỰ ĐỘNG TẠO CODE THỰC THI THỦ CÔNG các câu lệnh SQL (SELECT, INSERT, UPDATE, DELETE) ngay trong bộ nhớ mà bạn không cần gõ 1 dòng SQL nào!

   E. `@Configuration` & `@Bean` (tại `SecurityConfig.java`):
      - `@Configuration`: Chứa các thiết lập hệ thống.
      - `@Bean`: Đánh dấu một hàm trả về một đối tượng cần Spring quản lý (VD: `passwordEncoder()`, `securityFilterChain()`).

   F. `@Transactional` (tại các hàm của `EmployeeServiceImpl.java`):
      - Spring dùng **AOP Dynamic Proxy** bọc quanh hàm này.
      - Trước khi chạy hàm: Tự động mở một Transaction DB (`BEGIN TRANSACTION`).
      - Nếu hàm chạy thành công: Tự động `COMMIT TRANSACTION`.
      - Nếu có lỗi/Exception xảy ra: Tự động `ROLLBACK TRANSACTION` để dữ liệu DB không bị sai lệch.

   G. `@PreAuthorize("hasAuthority('ROLE_ADMIN')")`:
      - Spring Security dùng AOP bọc quanh hàm Controller. Trước khi code trong hàm chạy, Spring soi kiểm tra Token người dùng có quyền `ROLE_ADMIN` hay không. Nếu không ➔ Ném lỗi `403 Forbidden` ngay lập tức!

PHẦN 2: CHẶNG ĐƯỜNG 8 GIAI ĐOẠN CỦA MỘT HTTP REQUEST (REQUEST LIFECYCLE)
================================================================================

Khi người dùng ấn nút trên giao diện Web ➔ Dữ liệu trải qua 8 giai đoạn chính:

[GIAI ĐOẠN 1: CLIENT FETCH API (JS)]
- File: `app.js`
- JS gọi hàm `fetch('/api/employees', { headers: { 'Authorization': 'Bearer ' + token } })`.
- Đóng gói thông tin gửi qua đường truyền HTTP.

[GIAI ĐOẠN 2: TOMCAT EMBEDDED SERVER & DISPATCHER SERVLET]
- Spring Boot Embedded Tomcat Server tiếp nhận HTTP Request ở Cổng 8080.
- Chuyển Request tới trung tâm tiếp nhận `DispatcherServlet` của Spring MVC.

[GIAI ĐOẠN 3: SECURITY FILTER CHAIN (BẢO MẬT)]
- Request đi qua `JwtAuthenticationFilter.java`.
- `parseJwt()` lấy chuỗi Token ➔ `jwtUtils.validateJwtToken()` giải mã chữ ký HMAC SHA-256.
- Đọc `employeeId` và `role` ➔ Đăng ký đối tượng xác thực vào `SecurityContextHolder`.

[GIAI ĐOẠN 4: HANDLER MAPPING & CONTROLLER ROUTING]
- `DispatcherServlet` tìm Controller khớp với URL (VD: `GET /api/employees` ➔ `EmployeeController.getAllEmployees()`).

[GIAI ĐOẠN 5: JACKSON DESERIALIZATION & VALIDATION]
- Nếu có dữ liệu JSON gửi lên (POST/PUT), thư viện **Jackson** tự động giải mã chuỗi JSON thành đối tượng Java (`EmployeeRequest`).
- `@Valid` kiểm tra các luật dữ liệu (`@NotBlank`, `@Email`, `@Size`).

[GIAI ĐOẠN 6: SERVICE BUSINESS LOGIC & JAVA 8 STREAMS]
- Controller gọi `EmployeeServiceImpl.getAllEmployees()`.
- Service xử lý logic kiểm tra quyền Admin / Nhân viên thường.
- Dùng **Java 8 Stream API** (`employees.stream().map(...).collect(...)`) để biến đổi danh sách Entity thành DTO Response.

[GIAI ĐOẠN 7: REPOSITORY & HIBERNATE JPA DATABASE QUERY]
- Hibernate JPA dịch hàm repository thành câu SQL chuẩn (VD: `SELECT e FROM Employee e...`).
- Thực thi câu lệnh SQL tới H2 Database và nhận kết quả.

[GIAI ĐOẠN 8: DTO MASKING & JACKSON SERIALIZATION RESPONSE]
- Hàm `EmployeeResponse.fromEntity(emp, includeSalary)` kiểm tra quyền: Nếu không đủ quyền xem lương ➔ Gán `salary = null`.
- Jackson mã hóa đối tượng `ApiResponse` thành chuỗi JSON và gửi trả về Trình duyệt.

PHẦN 4: GIẢI THÍCH CHUYÊN SÂU KHÁI NIỆM KÈM VÍ DỤ CODE THỰC TẾ

1. TẠI SAO LẠI PHÂN CHIA CẤU TRÚC THƯ MỤC THEO "PACKAGE BY LAYER"?
--------------------------------------------------------------------------------
Dự án được phân chia theo cấu trúc tầng chuẩn Enterprise:
- `config`: Chứa toàn bộ các class thiết lập hệ thống (Security, Seed Data).
- `controller`: Chỉ chịu trách nhiệm tiếp nhận và phản hồi dữ liệu HTTP REST API.
- `dto`: Chứa các class đóng gói dữ liệu Request & Response.
- `entity`: Chứa các class ánh xạ trực tiếp với bảng trong Database (JPA).
- `exception`: Chứa bộ xử lý lỗi toàn cục tự động.
- `repository`: Chứa các interface truy vấn Database.
- `security`: Chứa các class xử lý thuật toán mã hóa Token JWT.
- `service` & `service/impl`: Chứa bộ não xử lý nghiệp vụ chính của ứng dụng.
- `util`: Chứa các hàm tiện ích dùng chung (tính tuổi).

=> LỢI ÍCH:
- Separation of Concerns (Phân chia trách nhiệm rõ ràng): Controller không quan tâm DB lưu thế nào, Repository không quan tâm ai gọi API.
- Tăng khả năng bảo trì và bảo mật: Khi sửa đổi DB hay thêm bảng mới, giao diện Web không bị ảnh hưởng.


2. ANNOTATION `@Transactional` LÀ GÌ? (CƠ CHẾ & VÍ DỤ CODE)
--------------------------------------------------------------------------------
- Công dụng: Đảm bảo tính toàn vẹn dữ liệu DB theo chuẩn ACID.
- Cơ chế AOP Dynamic Proxy:
  + Trước khi hàm chạy: Spring tự động mở một Giao dịch (`BEGIN TRANSACTION`).
  + Nếu hàm thực thi êm đẹp: Spring tự động chốt dữ liệu xuống DB (`COMMIT`).
  + Nếu giữa chừng xảy ra LỖI/Exception: Spring tự động RÚT LẠI toàn bộ các câu lệnh đã chạy trước đó (`ROLLBACK`), đưa DB về trạng thái an toàn ban đầu!

VD Code thực tế trong dự án (tại `AuthServiceImpl.java`):
```java
@Override
@Transactional
public AuthResponse register(RegisterRequest registerRequest) {
    // Bước 1: Lưu hồ sơ nhân viên mới vào bảng `employees`
    Employee savedEmp = employeeRepository.save(newEmp);

    // Bước 2: Lưu tài khoản mới vào bảng `user_accounts`
    UserAccount userAccount = new UserAccount(empId, encodedPass, role);
    userAccountRepository.save(userAccount);

    // 💡 NẾU Bước 2 bị lỗi (VD: Mất mạng DB hay trùng khóa):
    // Nhờ có @Transactional, dữ liệu ở Bước 1 sẽ TỰ ĐỘNG BỊ ROLLBACK XÓA KHỎI DB!
    // Tránh tình trạng "Hồ sơ nhân viên thì tạo được nhưng Tài khoản lại không có"!
    return new AuthResponse(token, empId, savedEmp.getFullName(), role.name());
}
```

Phân biệt:
- `@Transactional`: Dùng cho các thao tác Thêm/Sửa/Xóa (Write).
- `@Transactional(readOnly = true)`: Dùng cho thao tác Đọc dữ liệu (Read), giúp Hibernate tối ưu hóa bộ nhớ RAM và không tốn công theo dõi biến động dữ liệu (Dirty Checking).


3. `@Autowired` VS CONSTRUCTOR INJECTION TRONG SPRING BOOT
--------------------------------------------------------------------------------
Trong Spring Boot có 2 cách để tiêm (inject) Bean:

Cách 1: Dùng `@Autowired` trên thuộc tính (Field Injection - KHÔNG KHUYÊN DÙNG):
```java
@RestController
public class EmployeeController {
    @Autowired
    private EmployeeService employeeService; // Khó viết Unit Test, nguy cơ NullPointerException
}
```

Cách 2: Constructor Injection (CÁCH CHUẨN ĐANG DÙNG TRONG DỰ ÁN):
```java
@RestController
public class EmployeeController {
    private final EmployeeService employeeService;

    // Spring Boot 2.x/3.x tự động tiêm Bean qua Constructor mà KHÔNG CẦN gõ @Autowired!
    public EmployeeController(EmployeeService employeeService) {
        this.employeeService = employeeService;
    }
}
```
=> LỢI ÍCH CỦA CONSTRUCTOR INJECTION:
- Biến `final` đảm bảo tính bất biến (Immutability).
- Dễ dàng viết Unit Test (như file `EmployeeServiceTest.java`) bằng cách truyền Mock object trực tiếp vào Constructor mà không cần bật cả framework Spring.


4. JAVA 8 STREAM API & LAMBDA EXPRESSIONS (CÚ PHÁP & VÍ DỤ CODE)
--------------------------------------------------------------------------------
- **Lambda Expression (`->`)**: Cú pháp viết hàm ngắn gọn thay cho việc tạo Anonymous Class rườm rà.
  Ví dụ: `emp -> EmployeeResponse.fromEntity(emp, true)`

- **Stream API (`.stream()`)**: Bộ công cụ xử lý danh sách dữ liệu theo phong cách Functional Programming (Lọc, Biến đổi, Gom nhóm) cực kỳ tối ưu.

VD Code thực tế trong dự án (tại `EmployeeServiceImpl.java`):
```java
@Override
public List<EmployeeResponse> getAllEmployees(...) {
    List<Employee> employees = employeeRepository.findAll();

    // Dùng Stream API để biến đổi toàn bộ danh sách Entity thành danh sách DTO:
    return employees.stream() // 1. Chuyển List thành Stream chuỗi dữ liệu
        .map(emp -> {         // 2. Hàm map(): Biến đổi từng đối tượng Employee thành EmployeeResponse
            boolean includeSalary = isAdmin || emp.getEmployeeId().equalsIgnoreCase(requesterId);
            return EmployeeResponse.fromEntity(emp, includeSalary);
        })
        .collect(Collectors.toList()); // 3. Thu thập toàn bộ kết quả về dạng List<EmployeeResponse>
}
```


5. MÔ HÌNH DTO (DATA TRANSFER OBJECT) & BẢO MẬT DỮ LIỆU
--------------------------------------------------------------------------------
Tại sao KHÔNG TRẢ TRỰC TIẾP `@Entity` cho Frontend mà phải dùng DTO?
- Tránh lộ thông tin nhạy cảm: `UserAccount` chứa mật khẩu hash `password`, `Employee` chứa `salary`. Nếu trả Entity thẳng về màn hình, hacker có thể đọc được dữ liệu nhạy cảm.
- Tránh lỗi vòng lặp vô tận (Infinite Recursion) khi JSON Serialize các mối quan hệ bảng.
- DTO giúp linh hoạt che đậy dữ liệu theo phân quyền.

VD Code thực tế bảo mật Lương trong DTO (tại `EmployeeResponse.java`):
```java
public static EmployeeResponse fromEntity(Employee entity, boolean includeSalary) {
    EmployeeResponse response = new EmployeeResponse();
    response.setEmployeeId(entity.getEmployeeId());
    response.setFullName(entity.getFullName());
    response.setAge(entity.getAge()); // Đọc tuổi tính động từ getAge()

    // 🔒 NẾU includeSalary == false ➔ Gán lương = null để ẩn khỏi người dùng không có quyền!
    if (includeSalary) {
        response.setSalary(entity.getSalary());
    } else {
        response.setSalary(null);
    }
    return response;
}
```
